Developer notes — do not include on real pages

Prototype inputs: the page reads the locally displayed username and compatible browser-stored exam records; when none are available it uses labelled sample attempts so the dashboard can be reviewed visually.

Suggested production data contract: identify the learner from the authenticated server session, not from a client-supplied learner ID. Load a dashboard response containing the username or account alias, total exam attempts, latest attempt, best result, first-to-latest subject changes, topic aggregates, timing metrics and the last-updated timestamp.

Update flow: each completed exam should be saved by the backend before the results screen confirms completion. The dashboard should refetch after login, after a completed exam, on manual refresh and whenever the stored result version changes. All calculations must use persisted exam records belonging to the signed-in account.

Production access: protect this route on the server. Logout must invalidate the real session and return to the production login route. The current GitHub links are prototype navigation only, not production requirements.
